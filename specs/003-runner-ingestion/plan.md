# Implementation Plan: runner и ingestion

## Constitution Check

- Отчёт модели остаётся единственным контрактом между skill и ingestion; агрегаты в контракт не
  добавляются.
- Репозиторий команды обрабатывается как данные: код не запускается, hooks отключаются, в provider
  передаётся только очищенное окружение.
- Сырые ответы сохраняются до любой последующей обработки и не перезаписываются между запусками.
- Сниппеты читаются из зафиксированного SHA, а не из ответа модели.
- Все вычисляемые значения для UI записываются в статический bundle.

## Решение

Фича реализуется в существующем Go-модуле `agent` без сервера и базы данных:

1. `registry` читает YAML-реестр и определяет области репозитория.
2. `gitrepo` фиксирует SHA и создаёт read-only snapshot через `git archive` без checkout hooks.
3. `provider` предоставляет интерфейс для модели и headless command adapter с очищенным env.
4. `pipeline` выполняет retry/validation/enrichment с ограниченной параллельностью и lock-файлом.
5. `aggregation` считает таксономию, итог команды и детерминированный рейтинг.
6. `bundle` пишет `index.json`, `teams/*.json`, `rubrics/*.json`, `stats.json` и сохраняет raw.
7. `cmd/runner` предоставляет режимы `run` и `recalculate`.

Публичные интерфейсы между этапами остаются небольшими и тестируются на локальных репозиториях и
fake provider; сетевой вызов модели в тесты не входит.

## Проверки

- `go test ./...`
- интеграционный тест с локальным git-репозиторием, невалидным ответом и успешным retry;
- тесты ссылок/сниппетов, агрегации, ранжирования, лимита параллельности и lock-файла.
