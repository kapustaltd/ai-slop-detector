# Контракт: параметры адресной строки

FR-009: состояние сортировки и фильтров MUST отражаться в адресе, чтобы ссылку можно было
переслать. Это единственный «внешний интерфейс» страницы (кроме композиции UI), поэтому фиксируется
отдельно.

Роутинг — hash-режим (`createHashRouter`, спека 008 FR-003), поэтому полный адрес выглядит как
`#/?sort=total&dir=desc&status=all&warnings=1`.

| Параметр | Значения | По умолчанию (при отсутствии) | Источник истины |
|---|---|---|---|
| `sort` | `rank \| total \| backend \| frontend` | `rank` | `SortState.key` |
| `dir` | `asc \| desc` | `asc` при `sort=rank`, иначе `desc` | `SortState.direction` |
| `status` | `all \| done \| failed \| no_data \| running` | `all` | `FilterState.status` |
| `warnings` | `1` (наличие ключа = true, отсутствие = false) | отсутствует | `FilterState.warningsOnly` |

Правила:

- Неизвестное/невалидное значение любого параметра трактуется как значение по умолчанию (не
  ошибка, не падение страницы) — тот же принцип, что уже в `status()`/`sortKey` текущего кода.
- Изменение через UI обязано использовать `setSearchParams`, а не отдельный React state — иначе URL
  и экран могут разойтись.
- Удаление параметра при возврате к значению по умолчанию (например, `status: null` при выборе
  «все команды») — чтобы ссылки оставались короткими и совпадали для одинаковых состояний.
- Полное состояние восстанавливается из URL при монтировании страницы без дополнительного запроса
  (данные уже синхронно доступны через `getLeaderboardIndex()`).

Из объёма (см. `plan.md`, «Открытые расхождения», пункт 1): параметра для поиска по названию нет —
такого фильтра не реализуется в этой фиче.
