# Data Model: Непрерывный ход оценки

## EvaluationProgress

Текущий, привязанный к job ID snapshot состояния оценки команды. Содержит coarse stage существующего процесса, состояния областей, подтверждённое количество обработанных файлов, отметку времени и ограниченный журнал событий. Состояние не является оценочным отчётом и не используется при расчёте баллов.

## EvaluationEvent

Запись журнала в возрастающем порядке sequence:

- `sequence`: монотонный номер внутри прогона;
- `at`: UTC timestamp;
- `kind`: allowlist типа (`stage`, `scan`, `area`, `finding`, `report`, `error`);
- `title`: короткое безопасное описание;
- `detail`: необязательная конкретика, сформированная кодом из проверенных результатов;
- `area`: optional `backend` или `frontend`;
- `source`: optional проверенный путь и диапазон строк из опубликованной находки.

Свободный ответ модели, prompt и любые секреты не являются полями события.

## RubricProgress

Состояние существующей области оценки и список категорий из опубликованной рубрики. Пока отчёт области не опубликован, категория остаётся «В очереди»; активна только область, если pipeline подтвердил начало анализа области. Публикация валидной области переводит её категории в «Готово»; ошибка области — в «Ошибка».

## Lifecycle

`waiting → dispatching → runner_queued → analyzing → publishing → done` (или `failed`). Подсостояния областей и события сохраняются в snapshot текущего job directory; новый job начинает собственную историю.
