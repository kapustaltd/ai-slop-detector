# Feature Specification: Дата-бандл для UI

**Feature Branch**: `004-data-bundle`

**Created**: 2026-09-21

**Status**: Draft

**Input**: User description: "Вместо REST API — контракт статических данных: набор JSON-файлов, который пайплайн пишет, а статический UI читает напрямую. Сервера и базы данных нет."

## Overview

Между пайплайном и интерфейсом нет сервера — есть **дата-бандл**: набор JSON-файлов на диске,
который пайплайн записывает, а статический UI загружает. Эта фича описывает контракт бандла:
какие файлы, что в каждом лежит, как они связаны и как UI понимает состояние данных.

Бандл содержит только **готовые к показу значения**: все агрегаты уже вычислены пайплайном,
сниппеты уже вырезаны, ссылки уже построены. Интерфейс ничего не считает (принцип VI конституции)
и ничего не записывает (принцип V).

## Clarifications

### Session 2026-09-22

- Q: Макеты требуют подсветку кода на этапе сборки, с разметкой внутри бандла. Меняем контракт? →
  A: нет. Бандл хранит обычный текст сниппета, подсветка выполняется в интерфейсе в рантайме
  (решение: побеждает спека, дизайн адаптируется — см. `docs/design-deviations.md`).
- Q: Порог, при котором сравнение со всеми командами не показывается — 5 команд, как в макетах? →
  A: нет, остаётся 2.
- Q: Добавить в индекс число метрик с низкой уверенностью и долю проанализированных файлов, как
  в макетах? → A: нет. Состав индекса не расширяется, соответствующие элементы интерфейса
  снимаются.

### Session 2026-09-21

- Q: Нужен ли REST API и база данных? → A: нет. Данные статичны после прогона, интерфейс только
  читает — вместо API набор JSON-файлов.
- Q: Кто вычисляет агрегаты? → A: пайплайн; в бандл попадают готовые числа.
- Q: Нужны ли эндпойнты записи (перезапуск, переопределение)? → A: нет, платформа read-only
  (принцип V конституции); перезапуск — команда CLI у оператора.
- Q: Как обеспечивается доступ только для своих? → A: на уровне хостинга (приватный деплой,
  basic auth, VPN); собственной аутентификации в приложении нет.
- Q: Какова структура данных оценки? → A: три уровня таксономии (категория → подкатегория →
  метрика) плюс находки со сниппетами.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Индекс рейтинга одним файлом (Priority: P1)

Главная страница загружает один небольшой файл и сразу рисует рейтинг — не скачивая находки и
сниппеты всех команд.

**Why this priority**: определяет скорость главной страницы и всю схему разбиения данных.

**Independent Test**: собрать бандл на фикстурах и убедиться, что индекс содержит всё для
рейтинга и ничего лишнего.

**Acceptance Scenarios**:

1. **Given** собранный бандл, **When** загружается индекс, **Then** в нём есть по каждой команде:
   место, название, итог, баллы областей, статус, флаги, признак частичной оценки.
2. **Given** индекс, **When** проверяется его размер, **Then** он не содержит находок, сниппетов
   и обоснований.
3. **Given** команда без завершённой оценки, **When** она попадает в индекс, **Then** у неё
   указано состояние и отсутствуют выдуманные баллы.
4. **Given** индекс, **When** смотрят его метаданные, **Then** видны время прогона, версии схемы,
   рубрик, скиллов и модели.

---

### User Story 2 - Детали команды отдельным файлом (Priority: P1)

Страница команды загружает один файл этой команды и получает всё: баллы по всем уровням
таксономии, находки, сниппеты, ссылки, метаданные.

**Why this priority**: второй по важности экран; разбиение по файлам определяет, что страница
грузится быстро.

**Independent Test**: загрузить файл фикстурной команды и проверить полноту данных для всех
блоков страницы.

**Acceptance Scenarios**:

1. **Given** файл команды, **When** он загружен, **Then** в нём есть баллы категорий,
   подкатегорий и метрик по обеим областям.
2. **Given** метрика в файле, **When** смотрят её содержимое, **Then** доступны балл, `summary`,
   `rationale`, `confidence` и находки со сниппетами и постоянными ссылками.
3. **Given** находка с невалидной ссылкой, **When** она присутствует в файле, **Then** у неё
   стоит признак непроверенной ссылки, а сниппет отсутствует.
4. **Given** команда с одной областью, **When** загружается её файл, **Then** вторая область явно
   помечена как отсутствующая.

---

### User Story 3 - Рубрика как справочник «как оценивается» (Priority: P2)

UI показывает описание и якоря уровней, не зная рубрику наизусть: он читает её из бандла в той
версии, которой выставлены оценки.

**Why this priority**: делает баллы объяснимыми; без этого drill-down теряет половину смысла.

**Independent Test**: сверить файл рубрики в бандле с исходным YAML.

**Acceptance Scenarios**:

1. **Given** бандл, **When** загружается файл рубрики, **Then** в нём вся таксономия с весами,
   описаниями и якорями уровней плюс веса областей.
2. **Given** бандл, собранный по рубрике `backend.v1`, **When** проверяется соответствие, **Then**
   каждая метрика в данных команд присутствует в рубрике и наоборот.

---

### User Story 4 - Статистика для сравнения команд (Priority: P2)

UI рисует медиану и среднее по каждой категории и метрике, не вычисляя их на клиенте.

**Why this priority**: нужна для radar- и bar-графиков страницы команды.

**Independent Test**: собрать бандл на нескольких фикстурных командах и сверить медианы с
рассчитанными вручную.

**Acceptance Scenarios**:

1. **Given** бандл с несколькими оценёнными командами, **When** загружается файл статистики,
   **Then** по каждой категории и метрике есть медиана, среднее и число команд в выборке.
2. **Given** команды со статусом `failed`, **When** считается статистика, **Then** они не влияют
   на медианы, и это отражено в числе команд выборки.
3. **Given** менее двух оценённых команд, **When** собирается статистика, **Then** файл явно
   помечает недостаточность данных.

---

### Edge Cases

- Бандл пуст (ни одной команды) → индекс существует, помечен как пустой, UI показывает «нет
  данных», а не ошибку загрузки.
- Файл команды отсутствует, хотя команда есть в индексе → UI показывает ошибку данных, а не
  пустую страницу.
- Версия схемы бандла новее, чем понимает UI → UI показывает явное предупреждение о
  несовместимости, а не рисует частично.
- Очень много находок у команды → файл команды остаётся в разумных пределах за счёт лимитов на
  число находок и размер сниппетов из фичи 001.
- Бандл собран по разным версиям рубрики → такая сборка невозможна (003 FR-031), а UI
  дополнительно проверяет единственность версии.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Данные для UI MUST поставляться как набор статических JSON-файлов; сервер API и
  база данных MUST NOT использоваться.
- **FR-002**: Бандл MUST содержать индексный файл рейтинга со строками по каждой команде: место,
  название, итог, баллы областей, статус, флаги, признак частичной оценки.
- **FR-003**: Индексный файл MUST NOT содержать находок, сниппетов и обоснований.
- **FR-004**: Бандл MUST содержать отдельный файл на каждую команду со всеми уровнями таксономии,
  находками, сниппетами и постоянными ссылками.
- **FR-005**: Бандл MUST содержать файл рубрики каждой использованной версии: таксономия, веса,
  описания, якоря, веса областей.
- **FR-006**: Бандл MUST содержать файл статистики: медиана и среднее по каждой категории и
  метрике, число команд в выборке.
- **FR-007**: Все значения в бандле MUST быть вычислены пайплайном; UI MUST NOT пересчитывать
  баллы.
- **FR-008**: Каждый файл бандла MUST содержать версию схемы бандла и время сборки.
- **FR-009**: Бандл MUST различать состояния «нет данных», «оценка не удалась» и «готово».
- **FR-010**: Находки с невалидными ссылками MUST присутствовать в бандле с явным признаком, а
  MUST NOT вырезаться.
- **FR-011**: Структура и типы файлов бандла MUST описываться JSON Schema, а типы для UI MUST
  генерироваться из неё (принцип IX конституции).
- **FR-012**: Бандл MUST валидироваться по своим схемам сразу после сборки; невалидный бандл MUST
  считаться браком сборки.
- **FR-013**: Имена файлов команд MUST строиться по идентификатору команды детерминированно.
- **FR-014**: Бандл MUST быть самодостаточным: UI MUST работать, имея только его файлы, без
  обращений к внешним сервисам.
- **FR-015**: Операций записи MUST NOT существовать: перезапуск оценки и любые правки выполняются
  запуском пайплайна оператором.
- **FR-016**: Ограничение доступа MUST обеспечиваться средствами хостинга; собственной
  аутентификации в приложении MUST NOT быть.
- **FR-017**: Бандл MUST содержать перечень предупреждений (`warnings`) по каждой оценке в виде,
  пригодном для показа человеку.

### Key Entities

- **Индекс рейтинга (LeaderboardIndex)**: метаданные сборки и строки рейтинга по всем командам.
- **Файл команды (TeamBundle)**: полные данные одной команды — области, таксономия с баллами,
  находки со сниппетами, метаданные прогона, предупреждения.
- **Файл рубрики (RubricBundle)**: версия, таксономия с весами, описаниями и якорями, веса
  областей.
- **Файл статистики (StatsBundle)**: медиана и среднее по каждому узлу таксономии, размер
  выборки.
- **Метаданные сборки (BundleMeta)**: версия схемы бандла, время сборки, версии схемы отчёта,
  рубрик, скиллов и модели.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Главная страница загружает один файл; страница команды — не более трёх (индекс,
  файл команды, рубрика и статистика при необходимости).
- **SC-002**: Индексный файл на десятках команд остаётся достаточно малым, чтобы рейтинг
  отрисовывался менее чем за 1 секунду.
- **SC-003**: 100% файлов бандла валидны по своим схемам сразу после сборки.
- **SC-004**: UI полностью работает на фикстурном бандле без запуска пайплайна.
- **SC-005**: Любое расхождение структуры бандла с типами UI падает в тестах.
- **SC-006**: Публикация бандла — копирование каталога; развёртывание сервера или базы не
  требуется.

## Assumptions

- Бандл выкладывается вместе со статической сборкой UI (один каталог), поэтому загрузка идёт с
  того же origin и CORS не требуется.
- Размер данных — десятки команд, сотни метрик на команду, сниппеты ограничены лимитами из 001;
  суммарный объём бандла измеряется единицами-десятками мегабайт.
- Контракт бандла версионируется отдельно от контракта отчёта (001), потому что меняется по
  другим причинам — из-за потребностей UI, а не оценки.
- Ограничение доступа обеспечивается хостингом: приватный деплой, basic auth или VPN.

## Dependencies

- **001-evaluation-contract**: схема отчёта и рубрики (блокирующая).
- **003-runner-ingestion**: собирает бандл.
- **005-leaderboard**, **006-team-details**: потребители бандла.
