# Implementation Plan: Скиллы оценки

## Constitution Check

- **I–III:** каждый отчёт получает полный набор координат запуска; скилл не меняет версии
  рубрики и не выполняет агрегацию.
- **IV:** содержимое анализируемого репозитория обрабатывается только как недоверенные данные;
  найденные инструкции не становятся инструкциями для модели.
- **V–VI:** скиллы только оценивают метрики-листья и не выносят вердикт, не считают область,
  команду или рейтинг.
- **VII–IX:** контракт 001 и YAML-рубрики остаются единственными источниками структуры;
  скиллы не создают ручных дублей схемы или таксономии.
- **VIII:** статическая проверка артефактов дополняется ручным sanity-прогоном на двух
  репозиториях после появления контракта и рубрик.
- **X:** скиллы не требуют и не выводят секреты, сеть или API хостинга.

## Решение

Оба артефакта реализуются как узкие инструкции Claude Code с одинаковым протоколом и
различными значениями области/рубрик. Общий протокол описывается непосредственно в каждом
артефакте: Claude Code не поддерживает импорт одного `SKILL.md` в другой как обязательный
механизм, а дублирование процедуры не дублирует таксономию.

При запуске скилл:

1. принимает параметры области, пути, команды, репозитория и SHA;
2. читает соответствующий YAML и контракт 001, извлекая набор leaf-метрик и якоря;
3. проводит read-only разведку и исключает недоверенные/сгенерированные файлы;
4. собирает проверяемые evidence по каждой leaf-метрике;
5. выставляет балл только по якорям текущей рубрики;
6. печатает ровно один JSON-объект отчёта без markdown и пояснений.

Если контракт 001 или рубрика отсутствуют/не читаются, скилл не подменяет их собственной
структурой и не придумывает отчёт: запуск должен быть остановлен с диагностикой для runner.

## Файлы

- `.claude/skills/review-backend/SKILL.md` — backend-протокол, версия 1.0.0.
- `.claude/skills/review-frontend/SKILL.md` — frontend-протокол, версия 1.0.0.
- `scripts/test-review-skills.sh` — статическая проверка наличия обязательных инструкций и
  отсутствия захардкоженных leaf-метрик.
- `specs/002-review-skills/tasks.md` — исполняемый список задач.

## Вне объёма

- создание или изменение схемы отчёта и YAML-рубрик из 001;
- runner, повторы после schema error, проверка ссылок и сохранение нормализованного state;
- автоматическая калибровка, медианы и вычисление агрегатов;
- запуск кода команды, запросы к CI/PR/issues или любые сетевые обращения;
- формальный golden set: после готовности 001 требуется ручной sanity-прогон по FR-019.

## Проверка

До появления артефактов 001 проверяется структура инструкций. После их появления runner
должен выполнить каждый скилл на репозиториях разного уровня, проверить JSON по схеме,
покрытие leaf-метрик и существование evidence. Результаты sanity-прогона просматриваются
человеком; численные диапазоны в репозитории не фиксируются как обещание точности.
