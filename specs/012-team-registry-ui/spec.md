# Feature Specification: Управление реестром команд

**Feature Branch**: `012-team-registry-ui`

**Status**: Draft

## Goal

Оператор управляет командами из веб-интерфейса. Изменения сохраняются в YAML-реестре, который
читает текущий пайплайн оценки. Интерфейс результатов остаётся read-only.

## User Scenarios

### Добавить команду

Оператор задаёт ID, название, URL репозитория, ветку и активность. После сохранения запись попадает
в реестр и будет использована следующим запуском пайплайна.

### Обновить команду

Оператор меняет название, URL, ветку или активность существующей записи. ID остаётся неизменным,
чтобы не нарушать соответствие ID, bundle и сохранённых оценок.

### Удалить команду

Оператор подтверждает удаление. Последнюю запись удалить нельзя: пайплайн требует непустой реестр.
Сохранённые прошлые результаты не удаляются.

## Requirements

- В приложении есть отдельная страница «Команды» со списком и действиями добавить, изменить,
  удалить.
- API читает и атомарно обновляет тот же `registry.yaml`, что использует runner.
- API валидирует данные на сервере и отклоняет повторный ID, пустые обязательные поля и некорректный
  URL.
- Обновление не меняет ID и сохраняет пути областей, если форма их не редактирует.
- Изменения не меняют уже собранный bundle и не запускают оценку автоматически.
- Список и добавление команды доступны без токена. Изменение и удаление требуют bearer-токен;
  если `REGISTRY_API_TOKEN` не задан, эти действия отключены.
- Сервер по умолчанию слушает loopback. Развёртывание API в production не входит в эту фичу;
  текущий production остаётся статическим. Ссылка на управление появляется только при доступном API.
- Форма доступна с клавиатуры, имеет подписи и показывает состояния загрузки, ошибки, пустого списка,
  сохранения и успеха.
- Тексты управления на русском, без повторяющихся пояснений.

## Acceptance Criteria

- Из интерфейса можно создать команду, изменить её URL репозитория и удалить запись.
- Статус обработки обновляется без перезагрузки страницы. Если опубликована хотя бы одна
  обработанная область, оператор может открыть доступную часть отчёта до окончания прогона;
  отсутствующие области остаются без оценки.
- После перезапуска API изменения остаются в YAML-реестре.
- Runner читает изменённый реестр обычным способом.
- Без API ссылка управления скрыта. Добавление команды доступно без авторизации.
- Страница корректно работает на ширине 360 px и в обеих темах.
