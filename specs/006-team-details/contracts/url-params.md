# Контракт: параметры адресной строки страницы команды

FR-021: ссылка на раскрытый узел таксономии MUST быть адресуемой. Путь страницы —
`/team/:teamId` (уже существует); параметры ниже — query-строка поверх него, в hash-режиме
(`#/team/<id>?...`, спека 008 FR-003).

| Параметр | Значения | По умолчанию | Источник |
|---|---|---|---|
| `area` | `backend \| frontend` | не задан → обе области свёрнуты | `TaxonomyPath.area` |
| `node` | `<categoryId>` или `<categoryId>.<subcategoryId>` или `<categoryId>.<subcategoryId>.<metricId>` | не задан → дерево свёрнуто | `TaxonomyPath` |
| `finding` | `<file>:<line_start>-<line_end>` (см. research.md «Deep-linking находки») | не задан → раскрыта только первая/самая серьёзная находка метрики (DESIGN.md) | `findingSlug()` |
| `kind` | `strength \| issue` | не задан = все | `FindingsFilter.kind` |
| `severity` | `info \| minor \| major \| critical` | не задан = любая | `FindingsFilter.severity` |

Правила (те же, что в 005 `contracts/url-params.md`):

- `node` без `area` игнорируется (не открывает дерево наугад в обеих областях).
- `finding` без соответствующего `node` до уровня метрики игнорируется.
- Неизвестное/невалидное значение любого параметра → поведение по умолчанию, не ошибка.
- Изменение — только через `setSearchParams`, без отдельного React state.
- При возврате к состоянию по умолчанию параметр удаляется из адреса.
- Полное состояние (открытая ветка, фильтры, раскрытая находка) восстанавливается из URL при
  монтировании страницы, без дополнительного запроса (`TeamBundle` уже асинхронно загружен к
  моменту разбора адреса; до загрузки страница в состоянии `loading`).

Из объёма (см. `plan.md`, пункт 1 расхождений): параметра «только слабые места» нет.
