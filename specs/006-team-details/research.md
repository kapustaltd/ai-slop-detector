## Три состояния ссылки находки (DESIGN.md × контракт 001)

**Decision**: состояние ссылки вычисляется из **двух независимых** полей находки, а не из одного
`link_status`:

```
permalink отсутствует                          → «без постоянной ссылки» (копируемый путь, снипет показывается если есть)
permalink есть, link_status === 'verified'      → «рабочая» (кнопка «Открыть на <sha>»)
permalink есть, link_status — любое другое      → «непроверенная» (снипет НЕ показывается, даже если поле есть)
```

**Rationale**: `TeamFinding` хранит `link_status`, `snippet`, `permalink` тремя независимыми
опциональными полями, а не одним tri-state-полем. DESIGN.md описывает ровно три поведения
(«рабочая» / «непроверенная — код не показывается совсем» / «без постоянной ссылки — фрагмент кода
при этом показывается»), и различие между «непроверенная» и «без ссылки» — это разные ПРИЧИНЫ
отсутствия работающей кнопки (хостинг без шаблона vs проверка не прошла), а не разные значения
одного поля. `unverified`/`missing_file`/`invalid_range`/`unsafe_path` — все про неудачную
проверку уже существующей ссылки → снипет скрывается, даже если пайплайн его всё же прислал
(принцип IV: сниппет не должен показываться под меткой «непроверено», если ссылка, на которой он
основан, не подтверждена).

**Alternatives considered**: маппинг 1:1 `link_status → состояние` — отклонён, потому что тогда
для «без постоянной ссылки» (permalink отсутствует, link_status тоже может отсутствовать) не было
бы отдельного случая от `undefined`.

## Подсветка кода: перенос, а не переписывание

**Decision**: текущая Shiki-обвязка из `pages/team/ui/team-page.tsx` (`languageLoaders`,
`highlighterFactoryPromise`, `languageByExtension`, `snippetLanguage`, хук подсветки) переносится
почти дословно в `entities/finding/model/highlight-snippet.ts`, оборачивается в один хук
`useHighlightedSnippet(finding)`. Тема (`github-dark`/`github-light`) продолжает читаться из
`document.documentElement.classList.contains('dark')`.

**Rationale**: рабочая реализация уже прошла проверку (ленивая загрузка языка, соответствие теме,
graceful fallback на обычный текст при неизвестном языке/ошибке загрузки грамматики) — design-
deviations.md пункт 1 зафиксировал именно эту архитектуру (Shiki в рантайме, а не на этапе
сборки). Переписывать с нуля — не задача этой фичи (это редизайн вёрстки и разбор по FSD, не смена
архитектуры подсветки).

## AnchorScale: позиция балла между фиксированными якорями

**Decision**: шкала не линейна 0–10, а кусочно-линейна по отрезкам `[0,2]`, `[2,5]`, `[5,8]`,
`[8,10]` — каждый занимает равную долю ширины (25%) независимо от числовой длины отрезка, потому
что макет (`06-metric-drilldown.html`) размещает подписи 2/5/8/10 равномерно, а не пропорционально
значению. Позиция балла внутри своего отрезка — линейная интерполяция между соседними якорями.
Функция `anchorPosition(score: number): number` (0–100%) — в `entities/metric/model/contribution.ts`.

**Rationale**: соответствует макету «между якорями 2 и 5, ближе к 5» — расстояние до соседних
якорей визуально осмысленно только внутри отрезка, не в абсолютной шкале 0–10.

## Deep-linking находки без `id` в контракте

**Decision** (см. plan.md, пункт 6): слаг находки — `${file}:${line_start}-${line_end}`,
вычисляется на клиенте, не хранится и не требует правки контракта 001.

**Rationale**: детерминирован для конкретного `TeamBundle` (пайплайн не производит две находки с
одинаковыми файлом и диапазоном строк для одной метрики), этого достаточно для якоря на странице
одной команды. Настоящий стабильный `id` через прогоны не нужен — фича 005/006 работают с одним
прогоном на команду (Q9), сравнения находок между прогонами нет.

## Место в рейтинге и prev/next (см. plan.md, пункты 4–5)

**Decision**: `pages/team/ui/team-page.tsx` читает `getLeaderboardIndex()` (005, синхронный) по
`team_id`, ищет позицию команды и её соседей в уже отсортированном по `rank` списке индекса.

**Rationale**: индекс уже содержит `rank` и порядок; вычислять заново (например, пересортировывать)
запрещено принципом VI — используется порядок, в котором `teams` уже лежат в
`LeaderboardIndexBundle` (места присваивает пайплайн). Если индекс недоступен (страница команды
открыта напрямую по ссылке без захода на рейтинг) — блок «место в рейтинге» и prev/next скрываются,
а не падают.

## SHA без ссылки на коммит — контрактный пробел, не решение дизайна

**Decision**: `commit_sha` показывается как копируемый моноширинный текст, без кликабельной
ссылки. Ссылка на репозиторий и ветка из макетов (`04-06`) не выводятся — этих полей нет в
`TeamBundle`.

**Rationale**: FR-017 (сценарий 2, «клик по SHA открывает коммит») требует URL репозитория,
которого контракт 004 не несёт (только `commit_sha`). Строить ссылку без известного хостинга
запрещено 003 FR-021a. Это уже было так в дошаблонной реализации `team-page.tsx` (SHA — обычный
текст) — не новый пробел, внесённый редизайном. Зафиксировано как Q15
(`docs/open-questions.md`), не решается локально в рамках 006.
