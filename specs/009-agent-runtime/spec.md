# Feature Specification: Runtime агента архитектурного ревью

**Feature Branch**: `009-agent-runtime`

**Status**: Draft

## Overview

Эта фича добавляет локальный Go CLI, который принимает уже подготовленный репозиторий, читает
версионированную рубрику, отправляет ограниченный и отредактированный снимок кода во внешний
OpenAI-compatible agent API и возвращает только структурированный JSON-отчёт.

Это первый вертикальный срез будущего runner-пайплайна. Он не выполняет код анализируемого
репозитория, не хранит credentials в файлах и не считает агрегаты категорий или команды.

## User Scenarios & Testing

### User Story 1 — Анализ подготовленной рабочей копии

Оператор запускает CLI с путём репозитория, областью, commit SHA и рубрикой. Агент получает
инвентарь файлов и ограниченные фрагменты исходников, после чего выдаёт JSON-отчёт.

### User Story 2 — Безопасный вызов провайдера

API key, base URL, model и effort приходят из переменных окружения. В stdout, raw prompt и
ошибки ключ не попадает.

### User Story 3 — Отбрасывание недостоверного результата

Отчёт отклоняется, если нарушает контракт: неверный SHA, неизвестная метрика, score вне диапазона,
пустые findings, абсолютный путь, выход через `..` или ссылка на несуществующий диапазон строк.

### User Story 4 — Защита от prompt injection

Содержимое репозитория передаётся как недоверенные данные. Инструкции из README, комментариев и
исходников не могут менять правила агента. Подозрительные файлы помечаются в warnings.

## Requirements

- CLI MUST принимать `--repo`, `--area`, `--repo-id`, `--rubric` и необязательный `--output`.
- При отсутствии `--commit-sha` CLI MUST получить полный SHA через `git rev-parse HEAD` без
  выполнения команд из анализируемого репозитория.
- Scanner MUST игнорировать `.git`, `node_modules`, `vendor`, `dist`, `coverage`, lock-файлы и
  сгенерированные артефакты как источник авторского кода, но сохранять их наличие в инвентаре.
- Scanner MUST не отправлять `.env`, приватные ключи, credential-файлы и значения похожие на
  tokens/passwords.
- Provider adapter MUST использовать `Authorization: Bearer ...`, timeout и ограниченный ответ.
- Ответ агента MUST быть JSON без принятия markdown как протокола; для совместимости допускается
  снять единственную markdown-обёртку перед валидацией.
- Validator MUST требовать meta, одну запись на каждую metric leaf из рубрики, score 0..max,
  confidence, rationale и минимум одну finding на метрику.
- Validator MUST проверять существование файла и диапазон строк в локальном репозитории.
- CLI MUST сохранять только валидный нормализованный отчёт; невалидный ответ получает ненулевой
  exit code и безопасное описание причины.

## Non-goals for this slice

- PostgreSQL, HTTP API, очередь, UI и Caddy.
- Выполнение `npm`, `go`, Docker, тестов или CI из анализируемого репозитория.
- Автоматический расчёт итогов категорий и команды.
- Публикация API key или подключение секрета к серверу до ротации ключа.

## Acceptance Criteria

- `go test ./...` проходит без внешней сети.
- Клиент провайдера покрыт `httptest`-тестами: успешный ответ, HTTP error, timeout и отсутствие
  credentials.
- Scanner покрыт тестами на exclusions, truncation и redaction.
- Validator отвергает минимум пять классов невалидных отчётов.
- Fake provider позволяет локально прогнать полный happy path без реального API key.
- Ни один тестовый или примерный файл не содержит реальный ключ.
