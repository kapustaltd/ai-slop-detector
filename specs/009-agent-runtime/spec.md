# Feature Specification: Runtime агента архитектурного ревью — СНЯТА С ОБЪЁМА

**Feature Branch**: `009-agent-runtime`

**Created**: 2026-09-22

**Status**: Withdrawn (2026-09-22)

## Почему снята

Спека вводила отдельный путь оценки: Go CLI сам формирует промпт из снимка кода и отправляет его
во внешний **OpenAI-compatible agent API**. Это противоречит спекам 002 и 003, по которым оценку
выполняет скилл Claude Code (`review-backend` / `review-frontend`), читающий рубрику из
`rubrics/*.yaml`.

Решение владельца продукта от 2026-09-22: **идём строго по спеке, оценка — через скиллы**.
Конфликт спек разрешён в пользу 002/003.

Что было не так по существу, а не формально:

1. **Два мозга.** Формулировка задачи для модели жила и в `internal/agent`, и в
   `internal/pipeline`. Две реализации промпта и повторов расходятся при первой же правке.
2. **Процедура оценки исчезала.** Скилл описывает порядок: разведка структуры → сбор
   доказательств по каждой метрике → оценка строго по якорям. При отправке плоского снимка кода
   модель не ищет доказательства, а угадывает по срезу.
3. **`skill_version` терял смысл.** Он приходил флагом со значением по умолчанию `1.0.0` и не был
   связан с содержимым `SKILL.md`, то есть воспроизводимость по принципу I конституции держалась
   формально.
4. **Правка скилла ничего не меняла.** `.claude/skills/review-*/SKILL.md` не читал никто, кроме
   `scripts/test-review-skills.sh`.

## Что из неё сохраняется

Полезное из 009 не выбрасывается, а переходит в 003 как требования к вызову скилла:

- запуск без shell, только явные аргументы;
- рабочий каталог — подготовленная копия репозитория, код команды не исполняется;
- секреты платформы не наследуются дочерним процессом;
- отчёт отклоняется при нарушении контракта, с ограниченным числом повторов;
- в stdout, промпт и сообщения об ошибках не попадают credentials;
- покрытие тестами вызова скилла, включая таймаут и ошибку.

## Что уходит из кода

- `agent/internal/provider/openai.go` и `provider.OpenAIAdapter` — внешний OpenAI-совместимый
  провайдер;
- `agent/internal/agent` и `agent/cmd/slop-agent` — второй путь оценки со своим промптом;
- `pipeline.buildPrompt` в части дампа файлов и инструкций модели: формулировка задачи живёт в
  скилле, пайплайн передаёт только координаты прогона.

Исходная редакция доступна в истории git.
