# Пайплайн оценки

CLI на Go, который превращает репозитории команд в дата-бандл для интерфейса. Он оркестрирует
прогон, но не формулирует задачу модели: оценку выполняет Codex по skill-протоколу
(`review-backend` / `review-frontend`), читающий рубрику из `rubrics/*.yaml` (спеки 002 и 003).

## Что делает

1. Читает реестр команд (`registry.example.yaml` как образец).
2. Клонирует репозиторий и переключается на зафиксированный `commit_sha`. Клоны лежат **вне**
   дерева проекта — по умолчанию `../teams-repos/`.
3. Вызывает `codex exec` по каждой области без shell, в read-only sandbox и без сети.
4. Получает компактный structured output, разворачивает его в контракт 001 и валидирует.
5. Проверяет ссылки на код, вырезает сниппеты из клона по SHA, строит постоянные ссылки.
6. Считает агрегаты: подкатегории, категории, области, итог команды, места.
7. Складывает дата-бандл в `web/data/`, откуда его забирает сборка интерфейса.

Для возобновления и пересчёта сохраняется только нормализованный `state`; полные ответы модели
на диск не записываются.

## Запуск

```bash
# из корня репозитория; сначала один дешёвый canary
go run ./agent/cmd/runner run --registry registry.yaml --rubrics-dir rubrics \
  --output web/data --team team-01 --area backend

# полный прогон после проверки canary
go run ./agent/cmd/runner run --registry registry.yaml --rubrics-dir rubrics --output web/data

# пересчёт агрегатов без обращения к модели
go run ./agent/cmd/runner recalculate --registry registry.yaml --rubrics-dir rubrics --output web/data
```

Дефолт отчётов: `gpt-5.6-terra`, `medium`, без автоматического ретрая. Для ручного разбора
спорного результата: `--model gpt-5.6-sol --reasoning-effort high`. Каждый `--max-retries > 0`
разрешает новый полный платный вызов.

## Чего здесь нет

- Прямых обращений к API моделей: единственный провайдер — локальный `codex exec`.
- HTTP-сервера и control plane: запуск инициируется командой в терминале (спека 011 снята).
- Базы данных: хранилище — файловая система.
- Выполнения кода команд: их репозитории — данные, а не инструкции.
