# Работа со спецификациями

Спеки — источник правды выше кода. Меняется поведение — сначала спека, потом код.

## Где что лежит

- Конституция: `.specify/memory/constitution.md` — принципы, старше любой спеки.
- Спеки: `specs/<NNN-name>/spec.md`, рядом `checklists/requirements.md`.
- Скиллы Spec Kit: `.claude/skills/speckit-*` — `speckit-specify`, `speckit-clarify`,
  `speckit-plan`, `speckit-tasks`, `speckit-analyze`, `speckit-implement`.
- Журнал решений: `docs/open-questions.md`.

Номер каталога = порядок создания, а не приоритет. Текущая фича отмечается в
`.specify/feature.json`.

## Новая фича

1. Определи короткое имя из 2–4 слов, номер — следующий свободный в `specs/`.
2. Возьми структуру из `.specify/templates/spec-template.md`: Overview, Clarifications, User
   Scenarios (с приоритетами и Acceptance Scenarios), Edge Cases, Requirements (FR-NNN),
   Key Entities, Success Criteria, Assumptions, Dependencies.
3. Требования формулируй проверяемо: MUST / MUST NOT, одно требование — один факт.
4. Success Criteria — измеримые и без упоминания технологий.
5. Заполни `checklists/requirements.md`.
6. Коммит: `spec: <NNN> <о чём фича>`.

## Изменение существующей спеки

1. Найди все места, где живёт меняемое поведение: `rg "<ключевое слово>" specs/`. Изменение почти
   никогда не локально — смена решения в 003 обычно задевает 004, 005, 006.
2. Внеси правку во все затронутые спеки за один заход, иначе они разойдутся.
3. Запиши решение в раздел `## Clarifications` → `### Session YYYY-MM-DD` строкой
   `- Q: <вопрос> → A: <ответ>`.
4. Обнови `docs/open-questions.md`: статус вопроса и следствия по фичам.
5. Если правка противоречит конституции — правится конституция с повышением версии, а не спека в
   обход принципа.
6. Проверь, что не осталось хвостов снятого объёма:
   `rg "<снятая сущность>" specs/ docs/ .specify/`.
7. Коммит: `spec: <что решено и что из этого следует>`.

## Открытые вопросы

Ответ, которого нет ни в плане, ни в спеках, **не придумывается**. Он:

1. помечается в спеке как `[NEEDS CLARIFICATION: конкретный вопрос]`;
2. добавляется в `docs/open-questions.md` с указанием, какие фичи и требования от него зависят;
3. задаётся владельцу продукта с вариантами и рекомендацией.

Исключение — вопросы, делегированные платформе явно («предложи сам»): тогда решение принимается,
обосновывается письменно и фиксируется как предложение, которое можно отменить.

## Порядок стадий

`constitution → specify → clarify → plan → tasks → analyze → implement`.

Реализация не начинается, пока у фичи нет `spec.md`, `plan.md` и `tasks.md`.
Спека 001 блокирует всё: она задаёт контракт.

## Чего не делать

- Не расширять объём молча. Снятое остаётся снятым — см. `specs/007-jury-tools/spec.md`.
- Не переписывать спеку целиком ради правки одного требования.
- Не оставлять `[NEEDS CLARIFICATION]` в спеке, по которой уже идёт реализация.
