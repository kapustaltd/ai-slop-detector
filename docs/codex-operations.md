# Codex: разработка и генерация отчётов

## Два независимых контура

| Контур | Модель / effort | Назначение |
| --- | --- | --- |
| Интерактивная разработка | `gpt-5.6-sol`, `medium` | Изменения кода, ревью, отладка; `high` только для сложной архитектуры и безопасности |
| Пакетные отчёты | `gpt-5.6-terra`, `medium` | Один статический проход по репозиторию и рубрике |
| Ручная апелляция | `gpt-5.6-sol`, `high` | Только спорные результаты, не массовый прогон |

Интерактивные defaults лежат в `.codex/config.toml`. Runner всегда передаёт модель, effort,
read-only sandbox, отключённый web search и JSON Schema явно, поэтому пользовательская конфигурация
не может незаметно изменить отчёт.

## Почему прежний прогон падал и расходовал много токенов

Живые ответы показали два независимых отказа:

1. Один ответ содержал десятки лишних кавычек после `line_end` и пропущенную запятую. Обычный
   prompt «верни JSON» не гарантировал синтаксис.
2. Другой ответ уже разбирался как JSON, но 19 issue-находок не имели обязательного suggestion.
   Он также повторял известные pipeline-поля и писал `summary` вместе с похожим `rationale`.

Retry запускал новый процесс и повторно оплачивал чтение всего репозитория. Сырой attempt
сохранялся до декодирования, поэтому в нём не было причины отказа и token usage. Lock-файл создавался
через `O_EXCL`; аварийно завершённый процесс оставлял вечную блокировку.

## Новый поток данных

1. Go фиксирует SHA, обезвреживает инструкции команды и передаёт Codex только координаты.
2. Codex читает skill, YAML-рубрику и код в read-only sandbox.
3. `--output-schema schemas/review-output.schema.json` ограничивает ответ компактными полями:
   score, confidence, anchor, одна причина и 1–3 evidence на метрику.
4. Go добавляет meta/max, строит канонические summary/rationale, проверяет все metric IDs, файлы и
   строки, затем считает агрегаты.
5. JSONL-события сохраняют input/cached/output tokens. Стоимость остаётся нулевой, если Codex CLI
   не сообщает её; её нельзя достоверно вычислять без знания тарифа аккаунта.

Автоматические retry отключены. Ошибка и usage сохраняются в нормализованном state без полного
ответа модели; оператор сначала исправляет причину и только затем повторяет конкретную
команду/область с `--force`. Флаг
`--max-retries` оставлен как осознанный аварийный override.

## Безопасный запуск

Всегда начинайте с canary одной области одной команды (пример в `agent/README.md`). Перед полным
запуском проверьте:

- `codex login status` успешен;
- canary содержит все метрики и реальные диапазоны строк;
- token usage разумен, а `cached_input_tokens` появляется при повторяющемся контексте;
- `npm --prefix web run contract:check` и `go test ./...` проходят;
- в `web/data/state/<team>/<area>.json` нет секретов.

Не увеличивайте parallelism до проверки rate limits. При массовом прогоне дешевле продолжить с
сохранённого state, чем повторять уже успешные SHA. Runner переиспользует state только при
совпадении SHA, model, effort, rubric и skill version.
