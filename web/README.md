# Интерфейс платформы оценки

Статическое приложение: читает дата-бандл, собранный пайплайном, и показывает рейтинг команд и
разбор оценки по таксономии. Записей нет — инструмент только для просмотра (принцип V
конституции).

## Запуск

```bash
npm install
npm run dev
```

Приложение откроется на адресе, который напечатает Vite. Данные берутся из `data/` — сейчас там
фикстурный бандл.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | dev-сервер с горячей перезагрузкой |
| `npm run build` | production-сборка в `dist/` |
| `npm run preview` | просмотр собранного приложения |
| `npm run check` | формат, линт, границы FSD, типы и тесты — одной командой |
| `npm run lint` | ESLint, включая проверку границ слоёв |
| `npm run lint:fsd` | steiger: проверка структуры Feature-Sliced Design |
| `npm run typecheck` | проверка типов |
| `npm run test` | тесты (Vitest) |
| `npm run format` | форматирование Prettier |

Перед коммитом достаточно `npm run check`.

## Данные

Дата-бандл лежит в `data/` и подключается **импортом на этапе сборки**, а не запрашивается по
сети:

- `data/index.json` — индекс рейтинга, попадает в основной чанк;
- `data/teams/<team-id>.json` — данные команды, отдельный чанк на команду, грузится только при
  открытии её страницы.

Обновить данные — значит положить новый бандл в `data/` и пересобрать приложение. Все обращения к
данным идут через `src/shared/api/bundle.ts`: если понадобится перейти на загрузку в рантайме,
правится только этот файл.

Типы данных пока объявлены в том же модуле вручную и помечены как временные — их заменят типы,
сгенерированные из схем контракта 001 и бандла 004.

## Архитектура

Feature-Sliced Design. Слои снизу вверх: `shared` → `entities` → `widgets` → `pages` → `app`.
Импорт разрешён только вниз, обращение к внутренностям чужого среза запрещено — и то и другое
проверяется линтером, а не на ревью.

```
src/
  app/      инициализация: роутер (hash-режим), тема
  pages/    страницы: рейтинг, команда, «не найдено»
  shared/   ui (компоненты shadcn), api (доступ к бандлу), lib, config
```

Слой `features` не заведён намеренно: записей в системе нет, а сортировка и фильтры живут внутри
своих виджетов. Появится, когда возникнет функциональность, переиспользуемая между виджетами.

Слой `widgets` и `entities` появятся при реализации спек 005 и 006.

## Стек

Vite, React, TypeScript, shadcn/ui поверх Radix и Tailwind, TanStack Table, Recharts, Shiki,
React Router в hash-режиме, ESLint + Prettier, Vitest + Testing Library, steiger.

Маршрутизация в hash-режиме выбрана сознательно: прямые ссылки с фильтрами работают на любом
статическом хостинге без правил переписывания.

Внешних сетевых зависимостей во время работы нет: шрифт, иконки и стили локальные.
