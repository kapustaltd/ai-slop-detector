# Правила фронтенда

Статическое приложение, читающее дата-бандл. Подробности запуска — в `web/README.md`.
Стек и архитектурные решения зафиксированы спекой `specs/008-frontend-foundation/spec.md`.

## Архитектура: Feature-Sliced Design

Слои снизу вверх: `shared` → `entities` → `widgets` → `pages` → `app`.

1. Импорт только вниз по слоям. Проверяется `eslint-plugin-boundaries`, нарушение ломает линт.
2. Обращение к срезу — только через его `index.ts`. Импорт внутренностей чужого среза запрещён.
3. Внутри слоя срезы не импортируют друг друга.
4. Слой `features` не заводить, пока не появится функциональность, переиспользуемая между
   виджетами. Сортировка и фильтры живут в своём виджете.
5. Сегменты называются по назначению (`theme`, `routes`), а не по типу содержимого
   (`utils`, `helpers`, `types`). Проверяется steiger.

## Данные

1. Все обращения к бандлу — через `src/shared/api/bundle.ts`. Прямых импортов JSON из компонентов
   быть не должно.
2. Данные подключаются импортом на сборке. `fetch`, XHR и любые сетевые запросы в рантайме
   запрещены.
3. Индекс рейтинга — синхронно, файл команды — отдельным чанком через `loadTeam`.
4. Типы данных в `bundle.ts` временные и помечены комментарием. Когда появятся схемы 001 и 004 —
   заменить сгенерированными, руками не дописывать.
5. Приложение не вычисляет баллы, места и агрегаты — только отображает готовые значения из бандла.

## Интерфейс

1. Компоненты shadcn добавлять через `npx shadcn@latest add <имя>` — они попадают в
   `src/shared/ui/shadcn`. Вручную туда не писать.
2. `src/shared/ui/shadcn/**` исключён из ESLint, steiger и Prettier: это внешний код, который мы
   храним у себя. Правка такого компонента допустима, но осознанно.
3. Свои компоненты дизайн-системы — в `src/shared/ui`, рядом с тестом, экспорт через `index.ts`.
   Их шесть по инвентарю: `ScoreGauge`, `TaxonomyRow`, `AnchorScale`, `FindingCard`,
   `SeverityBar`, `EmptyState`.
4. Цвета, кегли, радиусы — только через токены из `src/app/styles/globals.css`. Литеральных цветов
   в разметке быть не должно. Значения токенов правятся только там, из
   `design/reference/tokens.json`.
5. `src/index.css` — файл shadcn: в нём только импорты, блок пресета и переназначение
   семантических переменных на `--ds-*`. Значения туда не добавлять.
6. Никаких внешних сетевых ресурсов: шрифты, иконки, стили — локальные.
7. Обе темы обязательны; шкала баллов в тёмной теме развёрнута — светлее значит выше.
8. Вёрстка держится от 360 px.
9. Операций записи нет: ни форм, ни кнопок действий, меняющих данные.

## Дизайн

1. Значения — из `design/reference/tokens.json` через токены `--ds-*` в
   `src/app/styles/globals.css`. Литеральных цветов и кеглей в разметке быть не должно.
2. Перед вёрсткой экрана читать его макет в `design/reference/screens/` и сверяться с
   `docs/design-deviations.md`: в четырёх местах макет расходится со спекой, и побеждает спека.
3. Порядок блоков, плотность и состояния брать из макета, не изобретать.

## Проверки

1. Перед коммитом — `npm run check` (формат, линт, FSD, типы, тесты).
2. Во время работы — узко: `npx vitest run <файл>`, `npx eslint <файл>`.
3. Тексты интерфейса на русском; тесты ищут элементы по роли и тексту, а не по классам.
